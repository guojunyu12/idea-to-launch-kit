# 技术适配声明

产品：AIGC 内容生成平台  
PRD：V7（2026-11-10）  
阶段：1 技术适配  
更新时间：2026-11-11

## 1. 产品形态判断

- 产品类型与核心任务：面向公众开放注册的模板驱动 AIGC 静态图片平台。普通用户登录后选择表情包、手机壁纸或电脑壁纸模块，选择已发布模板，输入提示词，选择尺寸和已启用模型，生成、下载或删除自己的图片。
- 管理侧任务：运营人员审核模板来源、版权和内容并发布模板；管理员管理模型、供应商、成本、限额、模块绑定和角色权限。
- 核心交互：一次生成；模板默认提示词与用户提示词组合后调用生图模型。V1 不做连续对话改图、参考图、局部重绘或生视频。
- 开发路径：后端先行。V7 新增账户、角色、额度、积分、模板状态、模型路由和审计等数据边界，先建立可测试的后端契约，再在阶段 3 重新接用户端和管理工作台；现有前端只作为旧版图片生成切片保留，不直接当作 V7 正式页面。
- 验收界面：阶段 2 使用 API/最小验收界面验证后端闭环；阶段 3 新建 V7 正式 Web 入口。旧版“上传人物照”页面不属于 V7 用户主流程，暂不删除，待确认后再决定是否移除或放入兼容入口。
- 上线套餐：腾讯云开发免费体验版，优先复用既有环境（引用台账 D9）。
- 当前阶段范围：确认 V7 的架构边界、数据模型、权限策略、模型/模板生命周期、子阶段路线和验收口径；不写业务代码。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| Python 3.12.x + FastAPI | 延续已有后端和工具包默认基线，适合图片任务、管理 API 和 pytest 验证。当前宿主 Python 3.13 只用于读取和工具检查，阶段开发环境继续使用现有虚拟环境并记录实际版本。 |
| Pydantic 请求/响应模型 | 为登录、角色、模板、模型、任务、积分和错误结构提供确定性边界。 |
| pytest + 真实冒烟脚本 | 业务状态、额度扣减、权限隔离、幂等和模型调用分别做 mock 与真实链路验证。 |
| SQLAlchemy + Alembic；开发 SQLite、生产 PostgreSQL | V7 有用户、角色、模板版本、模型配置、任务、积分、资产和审计等多实体关系，并要求公开注册、并发和账目一致；不能继续只靠简单文件结构。 |
| 本地受控文件目录；上线评估对象存储 | 图片属于大二进制；开发期延续现有目录，生产阶段结合 CloudBase 存储和 7 天清理策略评估。 |
| Next.js + TypeScript + App Router | V7 是 Web 产品，用户端和管理工作台需要独立入口、导航和权限态；延续现有前端工程作为基础。 |
| HttpOnly Cookie 会话 | 普通用户邮箱验证码登录；后台固定邮箱白名单；前端不保存长期令牌，后端执行角色权限。 |
| 代码控制的固定状态机 | 登录、模板审核、额度/积分、生成、删除和审计都由确定性代码编排；模型只负责生成图片，不决定权限、扣费或发布。 |
| 模型供应商适配层 | 保留当前 SenseNova 真实链路，同时支持 V7 要求的自定义模型、备用模型、超时、重试、单次成本和模块绑定。 |
| 手工导入模板优先 | V1 先支持运营人工导入和审核；外部平台连接器按需后置，避免未授权抓取和额外平台成本。 |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代方案 | 原因 | 影响 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| 先做单用户图片切片 | 先补账户、角色、额度和模型/模板状态，再扩展生成链路 | V7 面向公众开放，单用户默认归属已不够安全 | 阶段 2-1 会比旧版多做身份和权限基础；旧版生成 API 保留兼容但不作为新用户验收依据 | 若产品改回内部单用户试用，可缩小为固定测试账号 |
| 同步请求直接返回图片 | 提交任务 + 持久化状态 + 查询结果；队列由并发/耗时实测决定 | V7 有 P95、10 人并发和失败返还要求 | 前端需要任务状态页；后端必须支持重启恢复和幂等 | 实测所有任务稳定低于短请求阈值且并发不超过单进程边界时，可保留轻量同步实现 |
| 立即开放外部模板连接器 | V1 先人工导入、审核、发布；连接器后置 | V7 要求官方接口或人工导入，未授权抓取不能默认开启 | 首版模板数量增长慢，但版权边界明确 | 取得平台授权并有稳定接口后再接连接器 |
| V1 立即审核用户生成结果 | 只审核模板，用户生成结果暂不审核 | 阶段0已确认，先完成模板来源和发布闭环 | 页面和数据模型预留 review 状态，但不能宣称用户结果已审核 | 公开运营投诉或平台规则要求时再接结果审核 |
| 旧版上传人物照是新用户必经步骤 | V7 默认以文本提示词为核心；旧上传 API/页面先保留兼容，是否进入新页面待确认 | V7 用户流程没有参考图或人物照输入，继续强制上传会扩大范围 | 新版用户端先做文本提示词；旧数据和旧接口不删除 | 产品经理确认 V7 仍需人物照时，再将上传作为独立输入模块加入路线图 |
| 开发期接真实邮件服务 | 开发期固定测试码，生产阶段再接邮件服务 | 阶段0已确认，避免未评估的邮件费用和域名配置阻塞开发 | 阶段2只能验收会话边界，不能宣称邮件送达已验证 | 进入正式公开运营前必须完成邮件供应商、域名、限流和费用核对 |

## 5. 强制底线检查

- 密钥与隐私：计划通过。模型密钥只由后端 Secret/环境变量读取；邮箱验证码、用户提示词、图片和审核数据不写入公开日志；API 响应脱敏。
- 数据与任务可恢复：计划通过。账户、积分账本、任务、版本、资产元数据、模板版本、审核和审计均持久化；任务状态支持重启恢复。
- 输入输出校验：计划通过。邮箱、验证码、提示词、模块、模板、尺寸、模型 ID、上传文件和管理员配置均用 Pydantic/确定性规则校验；生成结果检查格式和尺寸。
- 错误与日志边界：计划通过。统一返回 `{"error":{"code","message"}}`；日志只记对象 ID、状态、耗时、成本摘要和错误类型，不记密钥或完整图片/提示词。
- 权限与高风险动作：计划通过。后端强制校验角色和对象归属；模板发布、模型启停、积分变更、删除和外部模型调用不交给模型自主决定。
- 测试与真实模型验收：阶段 2 先做 mock，再做 SenseNova 真实冒烟；V7 的 100 次成功率、P95 和 10 并发目标安排在专项验收，不用单次冒烟冒充硬指标。
