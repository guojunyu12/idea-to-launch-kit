# 阶段2-3技术开发文档

产品：图个乐  
阶段：2-3 任务历史与恢复  
更新时间：2026-11-08

## 1. 本阶段目标

把单次生成扩展为可追踪、可重试、可恢复的任务系统：保留历史版本，支持换模板重新生成，查询归属范围内的审计事件，并记录耗时与成本字段。

## 2. 本阶段交付

- `POST /api/v1/tasks/{task_id}/regenerate`：同一任务创建下一版本，可换模板；原图已删除时仍可重新生成，因为当前商汤调用是文生图。
- `GET /api/v1/audit`：只返回当前用户自己的审计事件，最多最近 100 条。
- 任务响应增加 `elapsed_ms`、`cost_cents`；成本未知时保持 `null`，不把未知成本写成 0。
- 生成成功后审计记录包含动作、版本号、耗时和成本字段；重新生成保留原版本。
- SQLite 使用 WAL 和 30 秒 busy timeout，减少页面连续操作和后台检查并发时的锁冲突。
- 启动时为已有 SQLite 数据库补齐新字段（`elapsed_ms`、`cost_cents`、`attempts`），不删除原任务数据。

## 3. 验收结果

- pytest：15/15 通过。
- 商汤真实冒烟：初次生成、重新生成、两版本历史、审计查询、结果下载和跨用户 404 通过。
- 重启恢复：随机标记重启检查通过。
- 数据库演进：已有旧 tasks 表字段迁移测试通过。
- 密钥扫描和文件位置检查通过。

## 4. 接口示例

```http
POST /api/v1/tasks/{task_id}/regenerate
X-Owner-ID: demo-owner
Content-Type: application/json

{"template_id":"wallpaper-sunrise"}
```

响应中的 `versions` 保留旧版本和新版本，`version_no` 递增；`GET /api/v1/audit` 返回同一用户的上传、生成和重新生成事件。

## 5. 边界与后续

当前成本字段只记录结构，不估算商汤实际账单；需要供应商价格、尺寸和计费规则确认后再接入成本计算。内容审核仍按产品决定暂不接入，只预留后台窗口。
