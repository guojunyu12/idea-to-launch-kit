# 阶段 3-1 技术开发文档：一级分类页与二级创作页

## 交付目标

把阶段 2 的临时 `/test` 工作台承接为正式的响应式 Web 页面。一级页负责选择创作空间，二级页负责在对应品类中选参考图、选输出比例、上传人物照片，并通过真实后端完成一次生成和结果下载。

## 技术实现

- 前端：Next.js App Router、TypeScript strict、React、Tailwind CSS v4 的 PostCSS 入口。
- 页面层级：`frontend/app/page.tsx` 是一级分类页，展示“表情包”和“手机壁纸”两个独立创作空间；`frontend/app/category/[kind]/page.tsx` 是二级创作页，只展示当前品类的模板参考图与生成工作台。
- 二级页布局：顶部品类标题与模板数量、图片优先的横向参考模板区、输出比例和上传照片的圆角创作条、结果预览与任务信息。
- API：`frontend/lib/api.ts` 统一调用后端模板、上传、任务和资产下载接口；默认 API 地址为 `http://127.0.0.1:8000`，可用 `NEXT_PUBLIC_API_BASE_URL` 覆盖。
- 校验：前端拦截缺失文件、JPG/PNG/WebP 以外格式和超过 10MB 的图片；后端继续执行图片真实格式与尺寸校验。
- 数据归属：上传、创建任务、下载资产都带 `X-Owner-ID`，沿用后端按用户隔离的数据边界。
- 跨域：后端允许本地 `127.0.0.1:3000/3001` 与 `localhost:3000/3001`，仅用于本地前端联调。
- 视觉：参考 `DESIGN (1).md` 的白色画布、照片优先、珊瑚红操作色、扁平卡片和 12px 圆角；窄屏改为单列，预览结果置顶。输入区提供输出比例选择，并实时显示对应的交付尺寸。

## 比例依据

- 表情包默认 `1:1`。Telegram 和 WhatsApp 的静态贴纸规范都以 512×512 方形画布为基准，因此方形是贴纸默认值。
- AIGC 比例选择覆盖 `1:1`、`4:3`、`3:2`、`16:9`、`3:4`、`2:3`、`4:5`、`9:16`，并补充 `9:19.5`、`9:21` 手机长屏选项。Midjourney 和 Google Imagen 的官方文档都把 1:1、3:2、2:3、4:3、3:4、16:9、9:16 等列为常用或支持比例。
- 用户反馈中的“9:6”不是主流 AIGC 比例；结合手机壁纸语境，本版按 `9:16` 处理。如果确实需要 9:6，可以再作为自定义比例加入。

参考：[Telegram 贴纸规范](https://core.telegram.org/stickers)、[WhatsApp 官方贴纸示例仓库](https://github.com/WhatsApp/stickers)、[Midjourney Aspect Ratio](https://docs.midjourney.com/hc/en-us/articles/31894244298125-Aspect-Ratio)、[Google Imagen 比例文档](https://ai.google.dev/gemini-api/docs/imagen)。

## 本阶段边界

本阶段完成代表页和首条生成链路，继续复用后端已有的重新生成、历史、审计接口，但不在页面中扩展历史管理。内容审核暂不启用，页面保留“审核后台窗口”状态位，后续阶段再接入规则与管理端。

## 启动方式

终端一：

```bash
cd projects/我的第一个产品/backend
set -a && source .env && set +a
.venv/bin/uvicorn app.main:app --port 8000
```

终端二：

```bash
cd projects/我的第一个产品/frontend
npm install
npm run dev -- --port 3001
```

打开一级页 `http://127.0.0.1:3001`，再进入二级页：

- `http://127.0.0.1:3001/category/sticker`：表情包模板与生成
- `http://127.0.0.1:3001/category/wallpaper`：手机壁纸模板与生成

本机 3000 端口被其他项目占用，因此本次验收使用 3001；后端健康检查仍为 `http://127.0.0.1:8000/healthz`。

## 验证口径

1. `npm test -- --run`：前端规则测试通过。
2. `npm run typecheck`：TypeScript 检查通过。
3. `npm run lint`：无错误；图片优化提示为 warning，不阻断交付，因为生成结果使用后端返回的临时对象 URL。
4. `npm run build`：Next.js 生产构建通过。
5. 页面手工验收：从一级页进入两个二级页；桌面宽度完成一次生成与下载；手机宽度确认单列布局、按钮可见、预览不溢出。
6. 后端回归：`backend/.venv/bin/python -m pytest -q` 与阶段 3-1 真实冒烟记录通过。
