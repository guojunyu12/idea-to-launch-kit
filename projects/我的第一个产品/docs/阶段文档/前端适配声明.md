# 前端适配声明

产品：图个乐  
阶段：3-0 前端适配  
更新时间：2026-11-08

## 1. 项目判断

- 产品类型：响应式 Web 图片创作工具。
- 主要用户：想做专属表情包和壁纸、不会写提示词或修图的年轻人。
- 主要终端：桌面 Web 和移动 Web；V1 不做原生移动端。
- 新项目或已有项目：已有阶段2后端项目；正式前端尚未建立。
- 本阶段业务目标：确定正式前端的技术、视觉、状态、路由和验收边界。

## 2. 输入资料

- PRD：已读取。
- 技术适配声明与决策台账：已读取。
- 阶段2界面类型：临时验收界面。`/test` 只用于当前验收，阶段3-1建立正式前端后停止对外依赖它。
- 接口文档：阶段2 API 已可运行，包含模板、上传、任务、重新生成、审计和产物下载。
- 设计稿：无；以本声明的视觉方向作为第一版代表页基线。
- 现有代码：有后端和临时测试工作台，无 `frontend/`。

## 3. 技术选择

- 框架与版本：Next.js App Router、React、TypeScript strict；版本取开工时稳定版本并锁定 lockfile。
- 样式与组件策略：Tailwind CSS + CSS 语义变量；优先原生 HTML 和轻量组件，复杂无障碍控件再引入基础组件。
- 数据请求与状态策略：同源 API 客户端集中管理；后端任务状态是事实来源，初期用 URL 任务 ID + React 状态，复杂缓存出现后再引入 TanStack Query。
- 流式通信策略：阶段3-1/3-2先用提交后查询；若真实耗时和状态刷新需要，再补轮询或 SSE。
- 表单方案：先用受控表单和运行时响应校验；复杂多步骤字段出现后再引入 React Hook Form + Zod。
- 测试方案：组件测试覆盖状态和错误；阶段3-2起用 Playwright 或等价脚本做真实浏览器闭环。
- 部署环境：阶段4再按腾讯云开发/云托管确定；前端运行时通过同源代理访问后端，不在浏览器放密钥。

## 4. 视觉方向

- 基底：暖纸色 `#F7F3EE`，让图片创作有工作台和纸张的触感。
- 主体：深墨色 `#151524`，用于导航、主要按钮和结果信息。
- 强调：珊瑚橙 `#FF6B5C` 表示行动与错误；酸橙绿 `#C6F36B` 表示成功和可继续；紫蓝 `#8F7AFF` 表示辅助交互。
- 字体：系统无衬线字体，中文优先 PingFang SC / Microsoft YaHei / Noto Sans CJK SC fallback。
- 密度：桌面三栏工作台，移动端单列；卡片圆角保持克制，结果图是页面视觉重点。
- 代表页：生成工作台，首屏直接呈现模板、上传、生成按钮和结果舞台，不用营销式长文案。

## 5. Agent 状态

后端状态 → 前端统一状态：

| 后端/接口状态 | 前端统一状态 | 页面表现 |
| --- | --- | --- |
| 未提交 | idle | 显示模板、上传和生成条件 |
| 请求发送中 | submitting | 禁止重复提交，按钮显示处理中 |
| `queued` / `running` | running | 显示任务号和当前阶段 |
| `succeeded` | succeeded | 显示产物、尺寸、下载和重新生成 |
| `failed` / 502 | failed | 显示错误原因和重试入口 |
| 网络断开 | disconnected | 保留任务 ID，允许重新查询 |
| 刷新后任务存在 | stale → running/succeeded/failed | 重新从后端读取真实状态 |
| 模板请求中 | loading | 骨架或明确加载状态 |
| 模板为空 | empty | 引导稍后重试，不显示为失败 |
| 任务不存在 | not_found | 显示任务不存在或已过期 |

阶段3-1只实现上述状态的基础映射；等待用户确认、取消、流式输出留到后续子阶段。

## 6. 页面与产物

- 核心页面：生成工作台、任务结果/历史版本面板。
- 核心闭环：进入工作台 → 选模板 → 上传图片 → 创建任务 → 查看真实生成结果 → 下载或重新生成 → 刷新后恢复任务。
- 产物类型：PNG 图片，按模板目标尺寸展示；浏览器预览不暴露本地绝对路径。
- 响应式目标：390px、768px、1280px、1440px。
- 前端子阶段规划：
  - 3-1 / 正式 Next.js 骨架、设计变量、生成工作台和真实模板/上传接口 / 产品经理在电脑和手机各完成一次上传并看到页面骨架。
  - 3-2 / 接通真实任务、结果预览、下载和失败重试 / 产品经理跑通一条真实生成闭环并刷新页面恢复结果。
  - 3-3 / 历史版本、审计入口、断线与任务恢复 / 产品经理重新生成并切换版本，确认任务不丢失。
  - 3-4 / 无障碍、响应式、Console 清理和生产构建 / 产品经理用手机完整走一遍并确认发布候选。

## 7. 偏离本手册的地方

- 阶段2留下的 `/test` 不按纵向切片保留，定性为临时验收界面；原因是它由 FastAPI 内嵌 HTML 提供，不满足正式 Next.js 工程的质量门槛。
- 阶段3-1不重复实现后端能力，只复用阶段2 API；影响是正式前端早期仍依赖现有 API 契约，契约变化需同步适配层。
