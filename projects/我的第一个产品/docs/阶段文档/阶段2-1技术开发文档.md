# 阶段2-1技术开发文档

产品：AIGC 内容生成平台（我的第一个产品）  
PRD：V7  
阶段：2-1 后端基础能力  
更新时间：2026-11-11

## 1. 本阶段目标

把 V7 的身份、权限和模板发布边界落到后端持久化层，形成可供后续生成链路和正式前端复用的稳定契约。本阶段只做基础数据与最小状态校验，不做新版生成页面、积分扣减、模型连接器或管理后台 UI。

## 2. 已实现范围

- `users`：邮箱归一化、`user/operator/admin` 角色、启用/停用状态和登录时间。
- `login_challenges`：开发期固定验证码的哈希、有效期、尝试次数和一次性消费。
- `sessions`：只存会话令牌哈希；客户端使用 HttpOnly、SameSite=Lax Cookie。
- 固定邮箱白名单由后端环境变量映射角色，客户端不能自带角色；普通邮箱默认 `user`。
- `templates` 与 `template_versions`：模块类型、尺寸、来源/版权字段、候选→审核→发布状态和版本快照。
- `model_configs` 基础表：只保存 `secret_ref` 引用，不保存实际模型密钥；完整 CRUD 与路由留在阶段2-3。
- `audit_events` 扩展操作者、角色和对象字段，旧 `owner_id/task_id` 兼容保留。
- 启动时把既有 JSON 模板导入数据库为 `legacy` 来源的已发布版本，兼容旧页面；新导入模板默认为 `candidate`。
- 公开模板接口只返回 `published`；旧的 `kind=wallpaper` 映射到 V7 的 `mobile_wallpaper`。
- 最小管理接口：人工导入候选、审核通过/驳回、发布；普通用户访问管理接口返回统一 403。
- 旧版 `/uploads`、`/tasks`、`X-Owner-ID` 接口保留，阶段2-2 再接入 V7 用户归属和文本提示词主链路。

## 3. 接口契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/auth/request-code` | `{email}`，返回挑战 ID、过期时间和投递模式；不回显验证码 |
| POST | `/api/v1/auth/verify-code` | `{challenge_id,email,code}`，成功写入 HttpOnly Cookie 并返回用户角色 |
| GET | `/api/v1/auth/me` | 返回当前会话用户；没有 Cookie 或已过期返回 `AUTH_REQUIRED` |
| POST | `/api/v1/auth/logout` | 撤销会话并清除 Cookie |
| GET | `/api/v1/templates?module=...` | 公开只读已发布模板；支持 `sticker`、`mobile_wallpaper`、`desktop_wallpaper` |
| GET | `/api/v1/admin/templates` | 运营/管理员查看所有模板状态 |
| POST | `/api/v1/admin/templates/import` | 运营/管理员导入候选模板，要求来源和版权状态字段 |
| POST | `/api/v1/admin/templates/{id}/review` | 运营/管理员执行 `approve` 或 `reject` |
| POST | `/api/v1/admin/templates/{id}/publish` | 仅审核通过模板可发布 |

统一错误结构为 `{"error":{"code":"...","message":"..."}}`。关键错误码包括 `AUTH_REQUIRED`、`ROLE_FORBIDDEN`、`INVALID_CODE`、`CODE_EXPIRED`、`CODE_ALREADY_USED`、`INVALID_TEMPLATE_STATE` 和 `TEMPLATE_NOT_FOUND`。

## 4. 状态与安全规则

- 登录邮箱统一 trim + lowercase；挑战码只存 SHA-256，不进响应和审计明文。
- 开发固定码仅在 `AUTH_MODE=dev_fixed` 使用；设置 `AUTH_MODE=production` 会在启动时直接拒绝，正式邮件服务放到上线阶段。
- `ADMIN_EMAILS`、`OPERATOR_EMAILS` 只在后端环境配置；同一邮箱不能通过请求体修改角色。
- 会话令牌只在 Cookie 发给浏览器，数据库只保存哈希；生产环境将 `SESSION_COOKIE_SECURE=1`。
- 模板状态必须先审核再发布；公开接口查询永远带 `status=published` 过滤，未发布模板不能被用户看到。
- 旧模板种子数据标记为 `source_type=legacy` 并兼容旧 `wallpaper` 名称；新模块正式名称为 `mobile_wallpaper` 与 `desktop_wallpaper`。
- 数据库继续使用 SQLAlchemy；本地 SQLite 通过幂等 `create_all` 和补列迁移启动，生产 PostgreSQL/Alembic 在上线前接入。

- 新增 4 条 V7 基础测试：邮箱归一化与管理员角色、Cookie 会话、普通用户 403、模板候选/审核/发布可见性、挑战码一次性消费。
- 保留并回归旧版上传、任务、版本、审计和 SenseNova 适配测试。

## 6. 本阶段不包含

新版用户端页面、管理员工作台 UI、文本提示词生成主链路、每日免费额度、积分账本、模型 CRUD/路由、正式邮件服务、用户生成结果审核、并发压测和生产部署。

## 7. 启动

```bash
cd projects/我的第一个产品/backend
.venv/bin/uvicorn app.main:app --reload --port 8000
```

开发期环境变量见 `backend/.env.example`：固定验证码模式、管理员邮箱白名单和运营邮箱白名单均只在本地配置；真实模式使用 `QWEN_IMAGE_API_KEY`、`QWEN_IMAGE_ENDPOINT` 和 `QWEN_IMAGE_MODEL=qwen-image-2.1-turbo`。打开 `http://127.0.0.1:8000/docs` 可查看接口契约。
