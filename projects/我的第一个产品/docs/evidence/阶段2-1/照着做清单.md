# 阶段2-1照着做清单（V7 后端基础）

## 1. 启动

打开终端，执行：

```bash
cd /Users/guo/Documents/通用项目/aigc-zhong-tai/projects/我的第一个产品/backend
.venv/bin/uvicorn app.main:app --port 8000
```

浏览器打开 <http://127.0.0.1:8000/docs>，再打开 <http://127.0.0.1:8000/healthz>。看到 `{"status":"ok"}` 算服务启动正确。

## 2. 普通用户登录

在 `/docs` 找到 `POST /api/v1/auth/request-code`，填入任意普通邮箱（例如 `user@example.com`）。把返回的 `challenge_id` 和本地 `AUTH_DEV_CODE` 填到 `POST /api/v1/auth/verify-code`。

验收标准：返回 `user.role=user`，浏览器保存名为 `aigc_session` 的 HttpOnly Cookie；`GET /api/v1/auth/me` 能读到同一个用户。不要把固定验证码写进截图或接口记录。

## 3. 角色隔离

在 `backend/.env` 的 `ADMIN_EMAILS` 或 `OPERATOR_EMAILS` 配置测试邮箱后重启服务，用该邮箱按第 2 步登录。

- 白名单管理员返回 `role=admin`，运营白名单返回 `role=operator`。
- 普通用户请求 `GET /api/v1/admin/templates` 必须是 403，错误码 `ROLE_FORBIDDEN`。
- 登录请求体不能传入或覆盖 `role`。

## 4. 模板审核与发布

用运营或管理员会话在 `/docs` 执行：

1. `POST /api/v1/admin/templates/import`，填写模板 ID、标题、模块 `desktop_wallpaper`、宽高、来源平台、来源 URL 和版权状态；返回 `status=candidate`。
2. 立即执行 `GET /api/v1/templates?module=desktop_wallpaper`，候选模板不能出现。
3. `POST /api/v1/admin/templates/{id}/review`，请求体 `{"decision":"approve","reason":"来源和版权已核对"}`；返回 `status=approved`。
4. `POST /api/v1/admin/templates/{id}/publish`；返回 `status=published`。
5. 再查公开模板列表，模板出现且带正式模块名。

如果跳过审核直接发布，应返回 `INVALID_TEMPLATE_STATE`。用 `kind=wallpaper` 查询旧版手机壁纸仍能看到兼容结果。

验收时请重点确认：普通用户看不到后台模板、候选模板不出现在公开列表、只有审核通过的模板能发布、会话 Cookie 存在且退出后失效。
