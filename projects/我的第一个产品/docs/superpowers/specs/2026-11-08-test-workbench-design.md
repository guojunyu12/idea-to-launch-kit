# 图个乐轻量测试工作台设计

## 意图

给产品经理一个立即可用的浏览器页面，验证当前后端的模板读取、图片上传、商汤生成、结果预览和用户隔离。页面服务于阶段验收，不承担正式产品首页职责。

## 目标与边界

- 目标：在 `/test` 完成“选模板 → 选图片 → 生成 → 查看结果与任务信息”的单页流程。
- 目标：显示清晰的成功、失败、模型和尺寸信息；结果图用前端 fetch 携带 `X-Owner-ID` 后再预览。
- 不做：登录、内容审核、历史版本管理、正式营销文案、Next.js 工程和新的后端业务接口。

## 方案对比

1. 在 FastAPI 内提供静态 HTML + 原生 JavaScript：零依赖，和当前 API 同源，最适合快速验收。
2. 新建 Next.js 前端：扩展性更强，但会提前进入阶段 3，增加构建与依赖成本。
3. 只使用 Swagger：开发成本最低，但无法连续验证上传、生成和结果预览。

选择方案 1，因为当前诉求是测试现有链路，页面可以随阶段 3 替换而不影响 API。

## 视觉与交互

- 配色：深墨蓝 `#151524`、暖纸色 `#F7F3EE`、珊瑚橙 `#FF6B5C`、酸橙绿 `#C6F36B`、紫蓝 `#8F7AFF`。
- 字体：使用系统无衬线字体，标题用较粗字重，正文保持短行和高可读性。
- 桌面布局：左侧流程控制，中间结果舞台，右侧运行状态；移动端改为单列。
- 视觉重点：结果舞台使用大面积留白和细网格，生成完成后由结果图占据舞台；动效只用于状态变化。
- 可访问性：表单有可见标签、按钮有键盘焦点、减少动态效果时关闭过渡。

## 实现约定

- 页面文件放在产品 backend 的 web 目录，由 FastAPI `/test` 返回。
- 前端只调用既有 `/api/v1/templates`、`/api/v1/uploads`、`/api/v1/tasks`、`/api/v1/assets/{version_id}`。
- 测试覆盖页面可访问性；真实链路继续由阶段证据中的冒烟脚本验证。
